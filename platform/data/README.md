## 2. Conventions

- **Numbers.** JSON numbers use a decimal point and no thousands separator (`1714.1`, `0.045`, `454111`). French formatting (`1 714,1`, narrow no-break space, comma decimal, `%` preceded by a no-break space) is applied **only at render time**. Never store formatted strings in a numeric field.
- **Units.** `EUR bn` = billions of euros, current prices. Every share states its denominator in `unit` **and** in `base`: `pct_gdp` (% of GDP), `pct_total_spending` (% of total public expenditure, TE), `pct_gni`, `pp_gdp` (points of GDP), `pct_population`, `pct_of_gap`, and so on. `validate.py` rejects a % without a denominator. A % of GDP and a % of TE must never be displayed unlabeled.
- **Ranks.** Rank 1 = highest value; `rank_of` gives the number of countries.
- **Ranges.** Where experts disagree, `range` (`low`, `high`) is filled and `value` may be null (for example the cost of a general return to retirement at 60, EUR 43-58 bn). When a lever or proposal has no published central value, the central is the midpoint and is flagged `central_is_midpoint: true`; it is a display convenience, not a source figure.
- **Status.** `verified` = canonical value; `caveat` = canonical but must be shown with its note (an "about" value, a fragile rank, a party figure, a convention-dependent estimate). No item flagged as unverified in the research base is included.
- **Sign convention (levers and proposals).** Positive EUR bn = improves the public balance (yield or saving); negative = worsens it (cost). Conversions keep the sign.
- **Denominators of conversions.** 2025 outturn: TE 1,714.1 bn, deficit 151.6 bn, population 68.998 m, GDP 2,991.1 bn. Amounts for 2026-2032 converted against these 2025 denominators are orders of magnitude (file 16 header).
- **Symmetry.** Every proposal carries `counter_argument_en` or `caveats_en`. Levers are grouped so that "Taxing the very wealthy" (R1-R5) and "Popular targets" (S13-S19) sit at the same level. Quiz items carry a `camp_coding`; the bank has as many left- as right-coded items, and `design.draw_rule` requires every draw to contain exactly as many of each (reference implementation and check in `validate.py`).
- **Claims.** `claim_status` (levers) and `status` (proposals) separate party claims, independent estimates, our own computations (`computed_by_us: true`) and observed outturns. Party claims stay grey and off by default in the simulator (Toggle 3).
- **Languages.** `*_en` is the reference text. `*_fr` labels and quiz wording are drafts for editorial review (`fr_status: draft_for_review` in the quiz).

## 3. Key fields

- `figures[]`: `id` (stable slug, never renamed), `label_en/fr`, `value`, `unit`, `base`, `year`, `vintage`, `source`, `source_id`, `url`, `range`, `rank_of`, `notes`, `status`, `origin` (`file00` or `topic_file`), `file00_row`, `source_file`, `match_text` (exact text to find in the research file when the number is not written as digits, for example "last of 27").
- `yardsticks[]`: `formula` (arithmetic over figure ids, parameters, earlier yardsticks and `mult_<class>_y1[_low|_high]`), `value`, `published_in_file20`, `checks_figure_id` (canonical figure the result must match), `date_from_day_of_year`/`value_date` (calendar dates).
- `levers[]`: `type`, `min`/`max`/`default`/`step`, `yield_low/central/high` (static, at the reference setting), `yield_static`, `yield_behavioral`, `yield_model` (`toggle`, `linear_per_unit`, `share_of_base` with `base_figure_id` and `max_share`, `positions`, `options`, `pool_not_yield`), `ramp_up_years`, `behavioral_toggle`, `multiplier_class`, `legal_feasibility`, `confidence`, `claim_status`, `political_origin`, `related_proposal_ids`.
- `proposals[]`: `claimed`, `claimed_path` (later-year claims, e.g. 2031), `estimates[]`, `range`, `derived.{claimed|range|claimed_YYYY}.{days_of_spending|pct_of_deficit|eur_per_inhabitant|pct_of_total_spending|pct_of_gdp}.{low|central|high}`, `published_conversions` (file 20 values the validator cross-checks).
- `questions[]`: `correct_value`, `figure_ids`, optional `formula` / `range_formulas` (recomputed), `misperception_ids`, `camp_coding`.
- `rating_actions[]`: `agency`, `date`, `action` (`downgrade`, `outlook_change`, `affirmation`, `review_listed_by_aft`), ratings and outlooks before and after, `match_text` found in file 06. Current grades are figures (`rating_*_oct2026_notches`, value = notches below AAA/Aaa, a display convention).
- **Chips in chapters.** `[[fig:id]]` resolves to `figures[]` or `rating_tables[]`; `[[yard:id]]` to `yardsticks[]`, then to `yardsticks.json` `parameters[]` (for example `[[yard:household_monthly_income_eur]]`, the EUR 3,000 editorial choice); `[[prop:id]]` to `proposals[]`; `[[src:id]]` to `sources.json`; `[[quiz:id]]` to a question or misperception. `[[yd:id]]` is accepted as an alias of `yard:` with a warning.

## 4. Update procedure

1. **A new vintage arrives** (for example the Insee 2025 COFOG tables in December 2026, file 20 §9.1). Update `research/00-reference-figures.md` first: file 00 stays the canonical source, with its reconciliation log and superseded table.
2. Edit the matching entries of `figures.json` (`value`, `year`, `vintage`, `source`, `url`, `notes`). Never change an `id`; add a new id for a new year and keep the old one if pages cite it. Add the old value to `superseded`.
3. Recompute derived values: `python3 -I validate.py --write-derived`. This rewrites `yardsticks[].value`, `proposals[].derived` and the share-of-base lever ceilings from `figures.json`.
4. If a file 20 published value changed, update `published_in_file20` / `published_conversions` after file 20 itself is updated.
5. Run `python3 -I validate.py` until it prints `Result: PASS`. Commit the data and the research change together, and add a changelog entry (file 20 §7.1).
6. New proposal or lever: add the entry with `source_ids` that exist in `sources.json` (add the source to the research file's source table first, then add it to `sources.json` with the same id) and `research_files` in which every number can be found.

## 5. What `validate.py` checks

1. JSON Schema of every dataset (`jsonschema` if installed, otherwise a built-in subset validator).
2. Unique ids; every referenced figure, yardstick, source, multiplier class, party, lever, proposal and misperception id exists; yardstick formulas only use ids defined before them.
3. Recomputes every derived value from `figures.json` and fails on a relative mismatch above 0.5%: yardsticks (and the values file 20 publishes, accepted when equal after rounding), proposal conversions, lever ceilings, quiz answers with a formula.
4. Greps the research markdown: each canonical figure must appear **in its own row** of file 00; each topic-file input must appear in its topic file; no figure may use a value listed in file 00 §4 (superseded). Reports how many figures file 20 quotes. Numbers in proposals and levers must appear in the research files they cite or in file 20 (warning).
5. Editorial rules: no unverified item; every % has a denominator; every proposal has a counter-argument or caveat; every lever has a user note; reports the balance of revenue vs spending levers and of quiz items by camp.
6. Quiz draw rule: equal numbers of left- and right-coded items in the bank; every draw size in `design.draw_rule` is feasible; 500 seeded draws of the reference procedure all respect the rule.
7. Rating history: unique ids, valid dates, `match_text` found in the research file.
8. Chapters (`fr/site/chapitres/*.md`, outside HTML comments and inline code): every chip resolves, `[[calc:]]` ids exist, no `[[fig-a-creer:]]` or « EN ATTENTE DE DONNÉES » remains. These errors are prefixed `chapters/` and counted separately ("Data errors: N; chapter errors: M"); `--data-only` skips checks 8 and 9.

9. **Chapter lints** on the displayed text only (`> ` lines, outside HTML comments, inline code, YAML front matter and the review-notes sections). Every message carries a `[code]`.
   - **Always errors (value mismatches).** `num-chip`: for every `[[fig:]]`, `[[yard:]]`, `[[prop:]]` and `[[calc:]]` chip, the number displayed in the same clause before it (French format: space or narrow no-break space as thousands separator, decimal comma, `%`, `€`, `milliards`, `jours`, `points`, ordinals and `e sur N` for ranks, day-of-year dates such as « 29 novembre » for `*_day` ids, spelled-out numbers and fractions such as « deux jours » or « un tiers », `X sur Y`) must round to the chip's value, `range.low`, `range.high`, value × 100 or value × 1000 (× 10 in a « sur 1 000 € » paragraph) at its own number of decimals; « environ » allows 6 %. An error is raised only when the unmatched number has a compatible unit and is within a factor 1.5 of the chip; otherwise `chip-mismatch` (warning). `calc-value`: a `[[calc:]]` formula is evaluated (ids, `yard:` prefixes, ranges low/high, wildcards `*`, `×`, `−`, `/`, `; ` sub-formulas, `= a à b` or `= a ; b` results, `%` results = × 100) and its stated result must match at its displayed precision (one unit off in the last place: `calc-rounding` warning).
   - **Errors with `--strict`, warnings otherwise.** `calc-no-id`, `calc-no-result`, `acronym` (first `>` occurrence on a page of a sigle from glossary §1 and §2.5, plus CICE, OFCE, OTAN, FMI, PISA, IGF, CEPEJ…, not expanded in parentheses in the same sentence), `estimate-leak` (an « Estimez d’abord » answer id or answer value shown before the answer in the same chapter, or anywhere in the previous chapter), `internal-ref` (`fichier N`, `notre base`, `research/`, `fig-a-creer`), `word-count` (visible words outside 1 500-2 200), `level-shown` (« Niveau : B1 » displayed).
   - **Warnings.** `chip-no-number` (a chip with no number before it), `calc-eval`, `calc-not-shown`, `unchipped` (a displayed sentence with a number that is not a year, date, step, chapter, question or page reference, age, didactic scale such as « sur 100 € », group size such as « 27 pays », and no chip; the message says when the chip sits only in another sentence or in a Pastilles/Visuel line), `rounding` (same id displayed with different roundings or « environ » forms across chapters; deviation from an optional `display` string in figures.json / yardsticks.json; yardstick shown with more decimals than its `display_decimals`), `same-number-ids` (same displayed number and unit chipped with two ids across chapters), `same-value-ids` (two ids rounding to the same value on one page, unless the page says « coïncidence »), `estimate-answer`, `estimate-repeat`, `denominator` (`%` without « du PIB », « des dépenses publiques », « de la population »… nearby, unless it is a growth rate, a « les 10 % les plus aisés » descriptor, or the chip's unit label appears in the sentence or paragraph), `typo-minus`, `typo-unit` (Md€, Mds, bn), `typo-ordinal` (2ème, 2nd), `typo-quotes`, `typo-dash`, `typo-range` (« 35-58 », « 2019-2024 » in running text), `typo-italics` (glossary §3 titles not in italics), `box-title`, `box-thesis`, `box-source` (italic source line with a §1.13 orientation label), `box-reply` (« Ce qu’on peut répondre »), `box-side` and `box-balance` (site-wide tally of `<!-- box-side: gauche | droite | les-deux -->` tags, warning when one side leads by more than 2), `orientation` (first mention of a §1.13 body without its exact label, or different labels across chapters), `banned-word` (glossary §4.4 « Éviter » terms outside « » quotations), `long-sentence` (> 25 words) and `long-paragraph` (> 60 words), one summary line per chapter (`--details` lists them all), `reading-time` (« Durée de lecture : environ N minutes » must equal round(words / 240)), `title` (H1 « # Chapitre N. Titre » with the title of fr/20-approche-pedagogique.md §2.1), `step-heading` (« ## Étape N. Titre », consecutive numbers), `chapter-ref` (« chapitre N, « Titre » » in text and buttons), `symmetry-gate`, `quiz-rounding` (a quiz explanation that rounds a figure differently from the chapters).
   - **Markers the chapters can use.** Context-only chip: `[[fig:id|contexte]]` (check 8 ignores the suffix) or `<!-- contexte: id -->` on the line or up to two lines above. « Estimez d’abord » answer: `<!-- estimez-réponse: id1 id2 -->` at the reveal, or a « Réponse : » / « Vraie valeur : » line whose chip matches the number after the colon (a `[[calc:]]` answer is checked by its displayed value). Box side: `<!-- box-side: gauche -->` just above or inside the box. Data symmetry gate: `<!-- symmetry-gate: ids=id_a,id_b | qualitative claim waiting for data -->` in the chapter notes; warns until every listed id exists in figures.json or yardsticks.json. The INFO lines also report, per chapter, the visible word count and the number of displayed sentences backed only by `[[src:]]`.
   - Options: `--strict`, `--no-lint`, `--details`, `--lint-only num-chip,calc-value,…`, `--chapters DIR` (lint another copy of the chapters).

10. **Lint exemptions** (`lint-exemptions.json`). Documented, exact-match exemptions for legitimate coincidences; today only `same-number-ids` can be exempted. An entry (`number` as displayed, `unit` as printed by the warning, `ids` as chip keys `fig:id`/`yard:id`, `reason_en`, `decided_by`, `date`) silences the warning only when the number, the unit and the whole set of ids match; a third id showing the same number is still reported. A malformed entry or an unknown id is a data error; an applied exemption is listed as INFO; an entry that matches nothing gives a `stale-exemption` warning. Registered on 2026-10-25: « 25 Md€ » (top of the Zucman proponents' range vs top of the « tax the rich » package) and « 47,2 % » (tax households paying income tax vs OECD tax wedge).

Run with: `python3 -I platform/data/validate.py`

## 6. Known editorial points (not errors)

- File 20 §3.3 says the budget calendar is "computed on 366 days (2024)", but its days (and `data/20_pedagogical_conversions.csv`) use 365. The yardsticks use 365.
- S16 (*Pouvoirs publics* + cabinets): file 20 rounds the base to 1.3 bn and shows a 0.65 bn maximum for a 50% cut; on the exact base (1.16 + 0.155 = 1.315) the maximum is 0.66 bn.
- Goal A (§5.2): file 20 divides a rounded 90 bn by 0.658 (136.8); on the canonical 89.6 bn the result is 136.2 (within 0.5%).
- Quiz balance (updated 2026-10-25): the 41-item bank has 11 right-coded and 11 left-coded items (plus 2 "anti-tax", 2 "pessimism", 4 "both", 11 general). File 20 §6.3 still lists 35 items; Q36-Q41 must be added there.
